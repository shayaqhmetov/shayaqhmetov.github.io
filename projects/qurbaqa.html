Pet project

Qurbaqa

Solo - api, web, mobile, admin

A personal life tracker: money, food, sport, goals and health in one place. The product mechanic is modules - you connect only the sections you need, and the app assembles around them, menu and assistant context included. On top of that sits light gamification: a pixel-art frog called Pilar, a pond that grows with every connected module, streaks, levels and XP.

A monorepo of four applications sharing one API, plus a pixel-art UI kit of my own, pixkit, published to npm from CI and used by both the React and the React Native clients.

Decisions worth asking about

Multi-currency without lying

Money is built around one rule: the rate is set by the user, frozen into the budget period, and never silently replaced by a market rate. Currency lives on the period, on every budget line and on every recorded expense. Amounts convert to the main currency at the frozen rate, and a currency with no rate is honestly excluded from the total and flagged rather than guessed at.

A budget from money, not from accounts

Instead of linking bank accounts, you take a snapshot of what you have right now and where, set a period until payday, split it by line, and get a daily limit that is recomputed each day from what is left. An overspend tightens the following days by itself, with no manual re-planning.

An LLM in production, for one job

Transaction categorisation runs through Claude Haiku with the user's own rules layered on top. The same path parses receipts from photos and PDFs and imports bank statements - a dedicated parser for Freedom Bank plus a generic tabular one, with text extraction from PDF.

Modules as an architectural contract, not as tabs

Connecting a module is user state that gates access on the server through a RequireModule guard, and changes navigation, tasks and data behind it. It runs through everything from the Prisma schema to the tab bar.

Design as the source of truth

Screens are built from artboards, with links to specific artboards kept in the code. Drift between design and code is fixed pointwise, with a written reason where the code departs deliberately - long amounts wrap rather than truncate with an ellipsis, for instance.

Engineering discipline

A spec-driven process on GitHub Spec Kit with 19 specifications, a BullMQ notification queue with per-user settings and reminders, optimistic mutations with rollback on both clients, a single refresh token shared across parallel requests, and end-to-end tests running on a real device.

What to look at

  • Connecting a module and watching the menu, the tasks and the pond change with it.
  • A budget period with two currencies and one frozen rate.
  • A receipt photographed and turned into categorised expenses.
  • The same pixkit components rendering in the web app and the mobile app.

Scale

  • Monorepo of four applications: API, web, mobile, admin
  • 48 mobile screens, 54 web views and components
  • Three languages (ru / en / kz) in every client, plus server-side localisation of reference data
  • 18 Maestro end-to-end scenarios and unit tests on the business rules
  • Native integrations: Google Sign-In, push notifications, Apple Health and Health Connect
