Pet project

99node

Solo - full stack

A roadmap builder. You lay out a map for a topic - "Python Programmer", "A holiday in Thailand" - then drill into any step and build a sub-roadmap inside it, to any depth. A map can be published to a catalogue, where it becomes a read-only page anyone can read without an account.

What separates it from a mind map is depth rather than canvas size. There is no single infinite sheet: every node is a plane of its own with local coordinates.

Decisions worth asking about

Local coordinates instead of an infinite canvas

Depth is implemented as a drill-down into a node, not as a zoom level. The consequence is that every query is bounded by a single plane and is therefore always fast: no tiles, no quadtree, no level-of-detail work was needed. There are three fixed scales and no free zoom, deliberately.

Hybrid canvas rendering

PixiJS over WebGL draws the grid and the edges; the cards live in a DOM layer above it. Text stays crisp at every scale, input and accessibility stay native to the browser, and the heavy graphics go to the GPU.

Privacy that is structural, not conditional

Visibility is a property of the map as a whole - there is no per-node flag. A public request checks it once, on the map, so the nodes of a private map are unreachable by structure rather than filtered out by a condition. Public pages never read the session cookie at all.

Derived values are never stored

Weights (a budget of 1 200 000 tenge, say) and periods are summed over the whole subtree with a recursive CTE on every read. Editing a leaf therefore cannot physically leave a stale figure on an ancestor. Measured on a map at the size ceiling - 1 500 nodes, documents around 2 KB - that is roughly 7 ms for weights and 10 ms for periods.

Periods show two numbers, not one

This is a product decision, not a technical one. Intervals do not add up the way quantities do, so a parent carries a calendar window - earliest start to latest end - and a total effort, separately. The gap between the two is the information: effort larger than the window means the steps run in parallel, effort smaller than the window means there is idle time between them.

One bad row cannot take down a plane

In PostgreSQL, casting '2026-02-31' to date does not normalise - it throws. A single date like that inside JSONB would turn the read of an entire plane into a 500. The cast therefore runs only under pg_input_is_valid inside a CASE, because CASE guarantees evaluation order and a plain AND does not.

Canvas groups are a label, not a container

A node does not reference a group and a group does not reference a node: membership is decided geometrically, by one rule shared between the canvas and the server-side render. Deleting a frame therefore cannot touch the cards inside it, and the system keeps exactly one hierarchy.

Optimistic UI throughout

IDs are generated on the client, so a card appears before the server answers. Writes go through a coalescing queue - a drag collapses into a single PATCH - and planes are cached with ETag revalidation, which makes stepping back up a level instant.

SEO is the only growth channel

Hence server-side rendering for public pages, a flat domain with no subdomains so no wildcard TLS certificate is needed, and slugs with homoglyph normalisation.
